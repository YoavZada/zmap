# v0.9.0 — "Hardening & Playground" (accessibility, error resilience, Sandpack playground)

**Date:** 2026-07-24
**Status:** Approved (design), pending implementation plan
**Baseline:** `main` after v0.8.0 merged (zmapgl 0.8.0; branch off 0993380).
**Branch:** `feat/v0.9.0-a11y-resilience-playground`

## Problem

Three production-readiness gaps remain before 1.0:

1. **Accessibility.** Most controls are well-labeled (MUI buttons with `aria-pressed`), but there are concrete gaps: the `<Map>` container has `aria-label="Interactive map"` but **no `role`**; `Popup` has no dialog semantics or focus management (opening doesn't move focus, closing doesn't return it, no Escape-to-close in zmap); `Tooltip` has no role; `LayerControl` group headings aren't associated with their checkboxes; `Legend` has **zero** a11y (invisible to non-visual users); the `TimePlayback` speed button has no `aria-label`. There is no automated a11y regression gate.
2. **Error resilience.** `new maplibregl.Map(...)` is called with no try/catch inside the create-once `useEffect` — WebGL-unavailable (or any constructor throw) propagates uncaught, and **a React error boundary cannot catch it** (the throw is in an effect, not render). No `map.on("error")` listener exists, so style/tile failures `console.error` silently. Layer hooks (`useMapLayer.addAll`, `useStyleReapply.apply`, raster/terrain) call `addSource`/`addLayer`/`setTerrain` unguarded — a bad spec throws synchronously and crashes the whole React tree.
3. **No live playground.** Examples are static (`CodeBlock`) or open in StackBlitz; there's no in-page editor to tweak zmapgl and see the map re-render.

## Decisions (locked with user)

1. **a11y scope: library + docs, axe-verified.** Fix the audited component gaps AND make the docs chrome axe-clean; add an axe scan to the e2e suite as a regression gate.
2. **Error resilience: themed fallback + resilient layers.** `<Map>` catches init/load failure and renders a themed fallback (`fallback`/`onError` props); GL layer components fail in isolation.
3. **Playground: one `/playground` page, lazy Sandpack, zmapgl from npm.** A dedicated route with a lazy-loaded `@codesandbox/sandpack-react` editor; zmapgl resolved from the published npm build inside the Sandpack iframe.
4. **Keyboard drawing is in scope** (added on review): a center-crosshair + native-pan model lets keyboard users place vertices for Draw/Measure and define a Select box — no mouse required.

## Workstreams

### W1 — Library a11y remediation

Fix only the audited gaps (well-labeled components — MapControls, GeocoderControl, DrawControl/MeasureControl/SelectControl toggle buttons, ContextMenu, Marker — are left alone):

- **Map container** (`components/Map/Map.tsx`): add `role="region"` to the outer Box (keep `aria-label="Interactive map"`). No `tabIndex` (the MapLibre canvas manages its own focus).
- **Popup** (`components/Popup/Popup.tsx`): add `role="dialog"`, `aria-modal="false"`, and `aria-label` from a new optional `ariaLabel?: string` prop (default `"Map popup"`). On open, move focus to the popup content container; **Escape** closes it (invokes the existing close path / `onClose`); on close, return focus to the element focused before open (`document.activeElement` captured at open). Non-modal — **no focus trap** (users must tab back to the map). Implemented with a `tabIndex={-1}` container ref + a keydown handler on the portal content.
- **Tooltip** (`components/Tooltip/Tooltip.tsx`): add `role="tooltip"` to its content.
- **LayerControl** (`components/LayerControl/LayerControl.tsx`): wrap each layer group in `role="group"` with `aria-labelledby` pointing at the group heading's id (generate ids with `useId`).
- **Legend** (`components/Legend/Legend.tsx`): add `role="img"` + an `aria-label` summarizing the mapping (e.g. `"Legend: <title> — <n> categories"` for swatches, or `"<title> color scale from <min> to <max>"` for a gradient), and associate the optional `title` via `aria-labelledby`.
- **TimePlayback** (`components/TimePlayback/components/TransportBar/TransportBar.tsx`): add `aria-label={\`Playback speed: ${speed}×\`}` to the speed button.

New public prop: `PopupProps.ariaLabel?: string` (JSDoc'd). No other API changes.

Tests (jsdom + testing-library, `fireEvent` — no new test deps): assert each role/label is present; Popup opens→focus moves in, Escape→closes + focus returns. Uses the existing `FakeMap`/`MapContext.Provider` pattern.

### W1b — Keyboard drawing (Draw / Measure / Select)

Make vertex placement and box selection operable without a pointer, using a
**center-crosshair + native map pan** model (chosen over a movable reticle for
robustness — the "cursor" is just `map.getCenter()`, no separate screen→geo
cursor state).

- **Crosshair overlay**: a shared private component
  `components/DrawLayers/components/KeyboardCrosshair/` (or a sibling shared
  internal) — an `aria-hidden`, `pointer-events: none` crosshair absolutely
  centered on the map container (`top/left: 50%`, `translate(-50%, -50%)`),
  rendered by `DrawControl`/`MeasureControl`/`SelectControl` **only while a tool
  is armed**. Styled via a colocated `*.style.ts` (theme-aware stroke).
- **Placement key — Space** (`hooks/useDraw.ts`): while armed, a keydown
  listener on the **map canvas** (`map.getCanvas()`, so it's scoped to canvas
  focus, not global) appends a vertex at `map.getCenter()` on **Space**, and
  `preventDefault()`s to suppress page scroll. This reuses the exact same
  vertex-append path the pointer `click` handler uses — center instead of the
  click point.
- **Unchanged keys**: the existing `window` keydown for **Enter = finish**,
  **Escape = cancel**, **Backspace = undo** stays exactly as-is (non-breaking).
  Space is the only new binding. (We deliberately did NOT repurpose Enter for
  placement, to preserve today's Enter-to-finish behavior.)
- **Native panning**: MapLibre's `KeyboardHandler` already pans the map with
  the arrow keys when the canvas is focused; verify the canvas is Tab-reachable
  (it carries `tabindex` by default) and add a focusable affordance only if a
  keyboard user cannot otherwise reach it.
- **SelectControl box** (`components/SelectControl/`): while armed, the first
  **Space** marks corner 1 at center, the next **Space** marks corner 2, and
  the box between the two centers drives the existing `pointInBox` selection
  (reusing the current box logic with two keyboard-captured corners). **Escape**
  resets the in-progress box. Keyboard select is **box-only** (lasso stays
  pointer-only — documented). A brief visible hint ("Space: set corner") while
  a corner is pending.
- **Docs**: the interaction/controls page and the a11y notes document the
  keyboard-drawing keys (arrows pan, Space places, Enter finishes, Esc cancels,
  Backspace undoes).
- **Tests** (jsdom + `FakeMap`): `useDraw` appends a vertex at `getCenter()` on
  a Space keydown dispatched to the fake canvas while armed, and does not while
  disarmed; Enter still finishes; SelectControl — two Spaces define a box that
  selects the enclosed points. `FakeMap.getCanvas()` already returns a real
  `<canvas>` element the test can dispatch a `KeyboardEvent` to.
- **e2e** (extends `keyboard.spec.ts`, W3): on `/interaction`, arm the draw
  tool, focus the map, press Space once or twice, and assert a draft
  vertex/feature appears (structure-only — via the draw feature count or the
  rendered draft layer), never pixels.

### W2 — Error resilience

`components/Map/Map.tsx` — new props (JSDoc'd):

```ts
/** Called with any error from map creation or the map's runtime "error" event. */
onError?: (error: Error) => void;
/** Rendered in place of the map if creation fails (e.g. WebGL unavailable).
 *  Defaults to a themed error panel. */
fallback?: ReactNode;
```

- Wrap `new maplibregl.Map(...)` (inside `create()`) in try/catch. On throw: set `mapError` state, call `onError(error)`, and do not proceed to wire the load handler. When `mapError` is set, render the `fallback` (or the default `<MapErrorPanel>`) inside the container Box instead of a live map.
- `instance.on("error", (e) => onErrorRef.current?.(e.error ?? new Error("map error")))` — forward async errors (non-fatal; today invisible). Registered in `create()` after construction succeeds.
- Default fallback: a new private `components/Map/components/MapErrorPanel/` (themed MUI Box — icon + "Unable to load the map" + the error message in dev), following the folder/style conventions. Not exported.
- **Resilient layers**: wrap the imperative work in try/catch so a bad spec logs (`console.error("zmap: …", err)`) instead of throwing:
  - `hooks/useStyleReapply.ts`: wrap the `apply(map)` invocation (mount effect + the reactive effect + the `ensure` re-apply) — protects Terrain, RasterLayer, and any consumer.
  - `hooks/useMapLayer.ts`: wrap the `addAll(map, cfg)` calls (protects GeoJSON/Point/Symbol/Heatmap/Choropleth/Hexbin/etc.).
  These log; they do not forward to `onError` (that's Map-scoped) — the map survives, the offending layer is simply absent.

**FakeMap test seam** (`test/mockMaplibre.ts`): allow a test to make construction throw — e.g. a module-level `setFakeMapConstructError(err | null)` that the `FakeMap` constructor checks and throws, reset in `resetFakeMaps()`. Tests: creation-throw → fallback renders + `onError` called + children absent; `fire("error", {error})` → `onError` called; a throwing `apply`/`addAll` → console.error, map + siblings unaffected.

## Out of scope (documented as known limitations)

Keyboard **lasso** selection (keyboard select is box-only; lasso stays
pointer-only); screen-reader live-region announcements for pan/zoom; RTL
layout; an exported `<MapErrorBoundary>` (the built-in fallback covers the init
case; child-render-error boundaries are the consumer's concern).

## Risks

- **Sandpack depends on CodeSandbox's external bundler CDN** (network) — e2e asserts only that the editor chrome renders, not full iframe execution; documented as a network dependency (same posture as the Photon/AWS defaults). If the CDN is down, the playground degrades to a code editor, not a crash.
- **Popup focus management** has edge cases (multiple simultaneous popups, popup whose trigger unmounts) — scoped to single-popup correctness; return-focus guards against a missing/detached previous element.
- **axe may surface pre-existing docs issues** beyond expectation — scoped to serious/critical; if a fix is genuinely large it's flagged to the user rather than ballooning the milestone.
- **`{ Map }` size** — the default fallback must not pull heavy static deps into the tree-shaken Map path; measured against the 4 kB budget as the guard.
