# v0.6.0 — "Runs anywhere" (SSR/Next.js story, guides, StackBlitz + starter)

**Date:** 2026-07-23
**Status:** Approved (design), pending implementation plan
**Baseline:** main after Batch 0 (zmapgl 0.5.1 on npm, changesets pipeline proven end-to-end).

## Problem

`import "zmapgl"` crashes plain Node in both module formats — the barrel's
`import "maplibre-gl/dist/maplibre-gl.css"` side-effect is bundler-only
(verified: ESM fails with `Unknown file extension ".css"`, CJS fails parsing
CSS as JS; `maplibre-gl` itself imports fine in Node). Next.js survives only
because webpack processes node_modules CSS; Vite SSR externals, Remix/React
Router 7, and any `react-dom/server` use die on import. The auto-CSS promise
is also already unreliable in bundlers: prod builds tree-shook the side-effect
despite `sideEffects: ["**/*.css"]` (why both apps import MapLibre CSS in
their entries since commit 89ea3d2). Map creation already lives in
`useEffect` and there is no module-scope `window`/`document` access — the
import crash and the missing `"use client"` marker are the whole SSR story.

## Decisions (locked with user)

1. **Explicit CSS import** — drop the side-effect; `import "zmapgl/styles.css"`
   becomes the one documented way (ecosystem norm). Semver-minor with a loud
   migration note.
2. **Tiny Next.js app in-repo, CI-gated** (`apps/next-smoke`) as the real
   SSR proof + guide reference.
3. **Guides shipping in 0.6.0:** Next.js & SSR; Migrating from react-map-gl.
   (Theming deep-dive and data-layers cookbook deferred.)
4. **Starter template lives in-repo** at `templates/vite` (degit), doubling
   as the StackBlitz payload source. No separate template repo.

## Workstreams

### W1 — Library: explicit CSS + `"use client"` (the only library change)

- Delete line 1 of `packages/zmap/src/index.ts`
  (`import "maplibre-gl/dist/maplibre-gl.css";`).
- `scripts/copy-css.mjs` stays (tsup `onSuccess`) — `dist/styles.css` and the
  `./styles.css` export are unchanged and become the primary story.
- **Delete `scripts/strip-css-dts.mjs`** and shorten the build script to
  `tsup && tsc -p tsconfig.build.json` — the script throws if the CSS import
  it strips is absent, so it must go in the same change.
- tsup config gains `banner: { js: '"use client";' }` (applies to both ESM
  and CJS outputs; marks the whole surface as client for RSC consumers —
  acceptable for a component library, documented in the guide).
- `sideEffects: ["**/*.css"]` stays (still correct for `dist/styles.css`).
- Changeset: **minor** (`0.6.0`) with the migration note: add
  `import "zmapgl/styles.css"` once (app entry or root layout); the package
  no longer injects MapLibre's CSS.

### W2 — `apps/next-smoke` + CI gate

- New workspace (matched by the existing `apps/*` glob): minimal Next 15
  app-router project, `private: true`.

    component (`app/MapView.tsx`, `"use client"` at top) mounting

  1. **SSR import check** — `node --input-type=module -e "await import('./packages/zmap/dist/index.js')"`

  2. **Next build (SSR smoke)** — `pnpm --filter next-smoke build`.
- Excluded from deploys automatically (deploy.yml/pages.yml filter docs +
  pathfinder explicitly).

### W3 — SSR regression test in the package

## Risks

- **0.5→0.6 upgrade without reading notes → unstyled map** (controls
  stacked, popups unthemed). Mitigations: changeset migration note, README +
  IntroPage + Next guide all show the one-liner, and the auto-CSS was
  already broken in tree-shaken prod builds.
- **`"use client"` on the whole barrel** marks even pure utils
  (`generateArc`) as client — acceptable for a component library; noted in
  the Next guide.
- **StackBlitz `^0.6.0` window** before the Version PR merges (see W5).
