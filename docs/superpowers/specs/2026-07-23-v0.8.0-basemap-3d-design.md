# v0.8.0 — "Basemap & 3D" (globe projection, terrain, raster layers, PMTiles)

**Date:** 2026-07-23
**Status:** Approved (design), pending implementation plan
**Baseline:** `main` after v0.7.0 merged (zmapgl 0.7.0; branch rebased onto d8bb6fe).
**Branch:** `feat/v0.8.0-basemap-3d`

## Problem

zmap renders a flat Mercator vector basemap and GeoJSON-driven layers. It has
no globe projection, no 3D terrain, no way to add raster (XYZ/WMS) tile layers,
and no PMTiles support. These are all first-class MapLibre GL 5 capabilities
(`setProjection`, `setTerrain`/`setSky`, `type: "raster"` sources, and the
`pmtiles://` protocol via `addProtocol`) that the library simply doesn't
surface. maplibre-gl@5.24 (already a dependency) supports all four natively.

**The unifying constraint:** `map.setStyle()` — called on every theme swap
(`colorScheme="auto"` light/dark flip) and provider change — wipes the entire
style document: custom layers **and** terrain, sky, and projection. Today only
`useMapLayer` re-applies its layers (on `styledata`/`idle`). Terrain,
projection, and raster layers each need the same re-apply-after-setStyle
treatment, so the spine of this milestone is a shared re-apply primitive.

## Decisions (locked with user)

1. **Hybrid API for globe/terrain:** `projection` is a `<Map>` prop (globe is
   one `setProjection` call, basemap-level like `provider`); `<Terrain>` is a
   child component that owns its raster-dem source + `setTerrain` + optional
   sky and re-applies on theme swap, like the layer components.
2. **PMTiles: lazy + auto-register.** `pmtiles` ships as a dependency but is
   `import()`-ed only inside `registerPmtilesProtocol()`; `<Map>` calls it
   automatically when it sees a `pmtiles://` URL. Off the tree-shaken `{ Map }`
   path; lands in a lazy chunk.
3. **Demos use free keyless sources:** AWS Terrarium terrain-RGB DEM tiles +
   keyless raster tiles. Fair-use posture, documented (Photon precedent).

## Shared primitive

`packages/zmap/src/hooks/useStyleReapply.ts` — extracts the re-apply guard that
`useMapLayer` pioneered, for reuse by the new terrain and raster hooks:

```ts
/**
 * Run `apply` once the map is loaded, and re-run it after every style swap
 * (setStyle wipes custom style additions). Runs `cleanup` on unmount.
 * `apply`/`cleanup` are held in refs so the effect is not resubscribed when
 * they change identity.
 */
export function useStyleReapply(
  map: MapLibreMap | null,
  loaded: boolean,
  apply: (map: MapLibreMap) => void,
  cleanup?: (map: MapLibreMap) => void,
): void;
```

Internally mirrors `useMapLayer.ts:100-118`: on mount `apply(map)`; register an
`ensure = () => map.isStyleLoaded() && apply(map)` on both `styledata` and
`idle` (the dual guard handles the setStyle race where the final `styledata`
fires before `isStyleLoaded()`); on cleanup, `off` both and run `cleanup`.
`apply` must be idempotent (re-adding an existing source/terrain is a no-op or
guarded). **`useMapLayer` is left untouched this milestone** (it is reviewed,
load-bearing, and GeoJSON-specific); a future refactor may adopt the primitive.

## Workstreams

### W1 — `useStyleReapply` primitive

- New hook + `packages/zmap/src/hooks/useStyleReapply.test.tsx` (jsdom, FakeMap):
  `apply` runs on mount when loaded; runs again on `styledata` and on `idle`
  only when `isStyleLoaded()`; skips when style not loaded; `cleanup` runs on
  unmount and listeners are removed; refreshing `apply`/`cleanup` identity does
  not resubscribe.
- Not exported from `src/index.ts` (internal).

### W2 — Globe projection (`<Map projection>`)

- `Map.tsx`: add `projection?: "mercator" | "globe"` to `MapProps` (JSDoc:
  default `"mercator"`; globe renders the map as a 3D sphere at low zoom).
- `Map` calls `useStyleReapply(map, loaded, (m) => m.setProjection({ type: projection }))`
  — the same primitive W1 introduces, with `Map` as a consumer. Default
  `"mercator"` still calls `setProjection` so switching back from globe (and
  re-applying after a theme swap) works. No bespoke second guard.
- **FakeMap** gains `setProjection`/`getProjection` (store + return the spec).
- Tests (`Map.test.tsx` additions): `projection="globe"` calls `setProjection`
  with `{ type: "globe" }` on load; re-applied after `fire("styledata")`;
  default omits globe (mercator). `{ Map }` size budget must not move
  materially (string prop + one call).

### W3 — `<Terrain>` component

`components/Terrain/{Terrain.tsx,index.ts}` (renders null; no `*.style.ts`).

```ts
export type TerrainProps = {
  /** Raster-DEM tile URL template or explicit tiles array. Defaults to the
   *  free AWS Terrarium elevation tileset. */
  demSource?: string | string[];
  /** DEM encoding. Default "terrarium" (matches the AWS default source). */
  encoding?: "terrarium" | "mapbox";
  /** Terrain vertical exaggeration. Default 1. */
  exaggeration?: number;
  /** DEM tile size. Default 256. */
  tileSize?: number;
  /** Add an atmospheric sky. `true` uses a sensible default; pass a spec to customize. */
  sky?: boolean | SkySpecification;
  /** Stable source id. Auto-generated when omitted. */
  id?: string;
  /** Escape hatch merged into the raster-dem source spec. */
  demSourceOptions?: Partial<Omit<RasterDEMSourceSpecification, "type" | "tiles" | "url">>;
};
```

- Default `demSource`: the AWS Terrarium tileset (`https://s3.amazonaws.com/elevation-tiles-prod/terrarium/{z}/{x}/{y}.png`, `encoding: "terrarium"`, `tileSize: 256`, `maxzoom: 15`) — exported as a documented constant `terrariumDem` so users can reference/override it.
- `apply(map)`: add the raster-dem source if absent, then
  `map.setTerrain({ source: id, exaggeration })`, then if `sky`
  `map.setSky(sky === true ? DEFAULT_SKY : sky)`. Wrapped in `useStyleReapply`.
- `cleanup(map)`: `map.setTerrain(null)` (+ `setSky` reset if set), remove the
  source. Gated on `loaded` (mounts only after Map's `loaded`, like all children).
- **FakeMap** gains `setTerrain`/`getTerrain`/`setSky` (+ track state).
- Tests: adds the DEM source + calls `setTerrain` with the exaggeration; `sky`
  adds sky; re-applies after `styledata`; `demSource` override respected;
  default uses `terrariumDem`; unmount calls `setTerrain(null)`.
- Barrel: `Terrain`, `TerrainProps`, `terrariumDem`.

### W4 — `<RasterLayer>` component + `useRasterLayer`

- `hooks/useRasterLayer.ts`: adds a `type: "raster"` source (`tiles`/`url`,
  `tileSize`, `attribution`, `sourceOptions`) + one `type: "raster"` layer
  (paint `raster-opacity`, `layerOverrides`, `beforeId`), built on
  `useStyleReapply`. Mirrors `useMapLayer`'s add/remove/re-add shape for a
  raster source instead of geojson.
- `components/RasterLayer/{RasterLayer.tsx,index.ts}` (renders null):

```ts
export type RasterLayerProps = {
  /** Stable id (source + layer share it). Auto-generated when omitted. */
  id?: string;
  /** XYZ tile URL template, or an explicit tiles array. */
  tiles?: string | string[];
  /** Alias for a single tile URL template. */
  url?: string;
  /** Tile size in px. Default 256. */
  tileSize?: number;
  /** Raster opacity 0–1. Default 1. */
  opacity?: number;
  /** Attribution shown for this source. */
  attribution?: string;
  /** Render this layer beneath the given layer id. */
  beforeId?: string;
  /** Per-role paint/layout patch: { raster?: LayerOverride }. */
  layerOverrides?: { raster?: LayerOverride };
  /** Escape hatch merged into the raster source spec (WMS, bounds, min/maxzoom). */
  sourceOptions?: Partial<Omit<RasterSourceSpecification, "type" | "tiles" | "url">>;
};
```

- Tests: adds raster source + layer; `opacity`/`layerOverrides`/`beforeId`
  honored; re-adds after `styledata`; unmount removes both.
- Barrel: `RasterLayer`, `RasterLayerProps`. (`LayerOverride` already exported.)

### W5 — PMTiles

- `providers/pmtiles.ts`:

```ts
/** Register the `pmtiles://` protocol on maplibre-gl (idempotent, dynamic import). */
export async function registerPmtilesProtocol(): Promise<void>;
/** True once the protocol has been registered. */
export function isPmtilesRegistered(): boolean;
```

  Implementation: module-scope `registered` flag; on first call
  `const { Protocol } = await import("pmtiles"); maplibregl.addProtocol("pmtiles", new Protocol().tile);`
  Guarded so concurrent/repeat calls register once. No top-level import of
  `pmtiles` (keeps it in a lazy chunk; SSR-safe).
- `Map.tsx` auto-register: when the resolved `provider` is a string style URL
  starting with `pmtiles://`, or a `StyleSpecification`/URL whose sources
  reference `pmtiles://`, call `registerPmtilesProtocol()` before/at map
  creation (client-only, in the load effect). Detection helper
  `usesPmtiles(input): boolean` in `providers/pmtiles.ts`. Await before
  `new maplibregl.Map` so the protocol exists when the style loads.
- `pmtiles` added to `packages/zmap/package.json` `dependencies`. Because it is
  only `import()`-ed, it stays out of the entry bundle — verify `{ Map }` and
  full-barrel budgets do not include it (dynamic import → separate chunk).
- Tests (`providers/pmtiles.test.ts`, node env): `vi.mock("pmtiles")` +
  spy on `maplibregl.addProtocol`; `registerPmtilesProtocol()` registers once,
  idempotent across repeated/concurrent calls; `usesPmtiles` detects
  `pmtiles://` in a URL string and in a StyleSpecification's sources, false
  otherwise. No e2e against a hosted archive.
- Barrel: `registerPmtilesProtocol`, `isPmtilesRegistered`.

## Out of scope

Single-image overlays (`ImageSource`, 4-corner), a standalone `<Hillshade>`
component (sky covers atmosphere; hillshade is a raster-dem paint story that can
come later), custom projections beyond globe/mercator, terrain-aware marker
elevation, a terrain-capable built-in `MapProvider` (terrain stays a separate
`<Terrain>` concern; the `MapProvider` interface is unchanged).

## Risks

- **AWS Terrarium tileset is fair-use/best-effort** — mitigated: documented,
  `demSource` fully swappable, and it's a demo/default not a hard dependency
  (Photon precedent from v0.7.0).
- **Terrain/projection re-apply race on theme swap** — mitigated: the shared
  `styledata`+`idle` guard, already proven by `useMapLayer`.
- **`pmtiles` dynamic import + SSR** — mitigated: client-only, async, never at
  module scope; `ssr.test.tsx` guards the regression.
- **Globe + terrain combined** — verify on maplibre-gl 5.24 (supports both);
  the terrain demo should be checked visually with globe on and off.
- **Bundle growth** — measured against size-limit; pmtiles stays lazy; the
  `{ Map }` budget is the tree-shaking proof.
- **Version** — v0.7.0 is released; this branch is based on 0.7.0, so the
  minor changeset resolves to 0.8.0 cleanly.
