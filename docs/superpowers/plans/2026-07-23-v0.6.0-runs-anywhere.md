> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make zmapgl importable and renderable everywhere React runs — explicit CSS import + `"use client"` banner, a CI-gated Next.js smoke app, SSR regression tests, two guides, and a StackBlitz-connected starter template.

**Architecture:** One library change (drop the CSS side-effect, add the banner) with regression nets at three levels (node-env unit test, plain-Node import check in CI, real `next build` in CI). Docs work rides existing patterns (pages/nav/e2e wiring identical to the Batch 0 `/changelog` task). The starter template is the single source of truth for both degit users and the StackBlitz button payload.

**Tech Stack:** tsup banner, react-dom/server, Next 15 (app router), @stackblitz/sdk, existing docs stack (Vite 8, MUI 7, prism CodeBlock).

**Spec:** `docs/superpowers/specs/2026-07-23-v0.6.0-runs-anywhere-design.md`

import { renderToString } from "react-dom/server";
import { describe, expect, it } from "vitest";
import Map from "./components/Map";
import Marker from "./components/Marker";

// Node environment (no jsdom, no mocked maplibre): proves the public
// surface server-renders without touching window/document. Children gate
// on the map "load" event, which never fires server-side.
describe("server-side rendering", () => {

    const html = renderToString(

        <Marker longitude={0} latitude={0}>
          <span>marker child</span>
        </Marker>

  });

```ts
import { defineConfig } from "tsup";

export default defineConfig({
  entry: ["src/index.ts"],
  format: ["esm", "cjs"],
  // d.ts comes from `tsc -p tsconfig.build.json` (second step of the build
  // script), not tsup: dts bundling needs the legacy TypeScript JS API, which

  clean: true,
  treeshake: true,

  banner: { js: '"use client";' },

  onSuccess: "node scripts/copy-css.mjs",
  // Keep React + MUI as peers; bundle nothing of them.
  external: [
    "react",
    "react-dom",
    "@mui/material",
    "@mui/icons-material",
    "@emotion/react",
    "@emotion/styled",
  ],

- [ ] **Step 7: Write the changeset**

Create `.changeset/explicit-css-use-client.md`:

```markdown
---
"zmapgl": minor
---

**CSS is now an explicit import.** zmapgl no longer injects MapLibre's stylesheet via a JS side-effect — add it once in your app entry (Vite `main.tsx`, Next.js root layout, etc.):

```ts
import "zmapgl/styles.css";
```

Why: the side-effect import made `import "zmapgl"` crash in plain Node (SSR frameworks, `react-dom/server`, Vite SSR externals), and bundler tree-shaking could silently drop it anyway. The package also now ships a `"use client"` banner, so zmapgl components can be imported directly from React Server Components.
```

resolve: {

    // source here (no dist), so map the subpath to MapLibre's CSS directly.

      replacement: "maplibre-gl/dist/maplibre-gl.css",
    },
    // (existing zmapgl→src alias, unchanged, now in array form)
